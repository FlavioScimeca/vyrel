Vyrel contains private applications. They are deployed or run directly; they are
not npm libraries.

<Cards>
  <Card href="/docs/apps/web" title="Web">
    Next.js frontend with authentication, onboarding, dashboard features, and
    Apollo GraphQL.
  </Card>
  <Card href="/docs/apps/mobile" title="Mobile">
    Expo React Native app with HeroUI Native, Better Auth, and local APK publish
    for fast Android installs.
  </Card>
  <Card href="/docs/apps/server" title="Server">
    Elysia/Bun API process that composes GraphQL Yoga, Better Auth, and REST
    adapters.
  </Card>
  <Card href="/docs/apps/docs" title="Docs">
    Fumadocs and Next.js application that renders the documentation you are
    reading.
  </Card>
  <Card href="/docs/apps/extension" title="Extension">
    WXT/React browser-extension scaffold with Chrome and Firefox targets.
  </Card>
</Cards>

## Development ports

| Application | Workspace | Port |
| --- | --- | --- |
| Web | `web` | `3001` |
| Server | `server` | `3000` |
| Docs | `docs` | `4000` |
| Extension dev tooling | `extension` | `5555` |
| Mobile | `mobile` | Metro (Expo; not a fixed HTTP port in this table) |

Storybook is part of the web workspace and runs separately on port `6006`.

## Shared contracts

The applications communicate through exported packages rather than shared
relative source paths. The web and mobile apps consume server types and
generated GraphQL artifacts. The server composes internal package
implementations. The docs and extension are currently lighter consumers of the
domain package graph.
