---
title: Environment and Constants
description: Runtime-safe configuration boundaries in @vyrel/env and @vyrel/consts.
---

Two packages keep environment parsing and derived constants out of feature code.

## `@vyrel/env`

The package exposes separate entry points:

| Entry point | Runtime | Contents |
| --- | --- | --- |
| `@vyrel/env/server` | Bun/server only | Authentication, database, R2, email, logging, profiling, runtime variables |
| `@vyrel/env/web` | Next.js/browser-safe | `NEXT_PUBLIC_SERVER_URL` only |
| `@vyrel/env/native` | Expo / mobile scripts | `EXPO_PUBLIC_SERVER_URL`, plus publish helpers `BUCKET_REPO` and `APP_SLUG` |

The server entry loads dotenv and validates `process.env`. The web entry passes
an explicit runtime object to `@t3-oss/env-nextjs`, preventing accidental
exposure of server values. The native entry uses `@t3-oss/env-core` with explicit
`runtimeEnv` members so Metro can inline `EXPO_PUBLIC_*` values. See the
complete [environment reference](/docs/getting-started/environment) and
[Local APK publish](/docs/apps/mobile/local-apk-publish).

`envBoolean` normalizes actual booleans and common string forms. Only `1`,
`true`, `yes`, and `on` are true; other strings are false.

## `@vyrel/consts`

Runtime-specific entry points prevent browser modules from importing server
configuration accidentally.

| Entry point | Important constants |
| --- | --- |
| `@vyrel/consts/server` | GraphQL endpoint path, one-day JWT expiration, ten-hour JWKS cache TTL |
| `@vyrel/consts/web` | Browser token identifiers and GraphQL URI derived from the public server URL |
| `@vyrel/consts/native` | Empty placeholder for a future native runtime |

## Usage rule

Import the narrow runtime entry point. Do not add a barrel that exports server
and browser constants together; doing so weakens the environment boundary and
can pull private configuration into client bundles.
