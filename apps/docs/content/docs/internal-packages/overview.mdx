Internal packages are private workspaces under `packages/*`. They let multiple
applications share infrastructure and domain behavior without turning the
repository into one undifferentiated application.

## Stability

These package names make ownership explicit, but they are not public
compatibility contracts. Internal exports can change with their consumers in
the same pull request. Public packages use a separate release and semantic
versioning process.

## Import policy

Consume an internal package through the exports declared in its
`package.json`. Most internal packages use source exports and do not need a
separate build. The package must be listed as a `workspace:*` dependency of the
consumer so Turborepo can understand the relationship.
